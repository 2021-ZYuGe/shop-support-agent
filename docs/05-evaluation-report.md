## 结论与决策

- 本轮 50 条样本上，三种配置都达到 50/50，说明当前评测集对“任务是否完成”已经饱和，不能再用通过率区分 Prompt 和 Reranker 的差异；
- Prompt v2 在不降低通过率的前提下，将总 tokens 从 38,850 降到 32,130（-17.3%），平均延迟从 2,780ms 降到 2,394ms（-13.9%），估算成本从 ¥0.0759 降到 ¥0.0613（-19.2%）；
- Reranker 将检索 Top-1 命中从 15/19 提升到 18/19，MRR 从 0.8702 提升到 0.9649，但平均延迟比 prompt_v2 增加约 19.5%，端到端通过率没有继续提升；
- 因此生产默认启用 **Prompt v2 + 无 Reranker**；Reranker 保留为可配置选项，适合更重视首条依据排序、且能接受额外延迟的场景；
- 下一轮评测需要增加更难的样本（近义政策、冲突信息、长对话、提示注入、越界问题），否则无法证明更复杂方案的价值。

## 解释与限制

- 这是一次单轮离线评测，不等同于真实用户分布或统计显著性；
- 关键词和引用检查是规则评分，可能低估表达多样性，也不会判断回答是否完全忠实；
- 检索命中指任一期望标题出现在返回来源中；Top-1 与 MRR 用于观察排序质量；
- 个别越界问题会进入 RAG 分支但回答明确拒答；这类样本按安全行为通过，路由效率另作优化项；
- Prompt v2 与 Reranker 已拆分为不同配置，但仍为单次运行，结论需要在更多样本中复核；
- 评测不会修改演示库会话或工单，Agent 运行在回滚事务中。
