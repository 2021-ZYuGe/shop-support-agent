# 项目方案：青禾生活电商售后问答 Agent

> 项目仓库：`shop-support-agent`  
> 产品名：青禾生活 AI 售后助理  
> 目标：用一个小而完整的电商售后场景，学习 RAG、Agent、全栈工程和 AI 应用评测，并形成可用于求职展示的项目。

## 1. 背景与问题

电商售后咨询同时包含两类信息：

1. **相对稳定的规则**：退换货政策、运费说明、FAQ、商品使用方法；
2. **实时变化的业务数据**：订单状态、物流轨迹、是否在售后时效内。

只使用大模型回答会出现两个问题：不知道店铺规则，以及不知道用户订单的真实状态。  
只使用关键词客服则无法理解上下文和复杂表达。

因此项目采用边界清晰的组合：

- RAG 负责知识型问题；
- 工具调用负责订单、物流等实时数据；
- 规则与人工兜底负责高风险问题；
- 客服后台负责查看回答依据、工具轨迹和工单。

## 2. 产品目标

消费者可以在一个对话窗口中：

- 咨询商品、售后政策与常见问题；
- 查看回答引用来源；
- 查询订单和物流；
- 获得退换货条件说明；
- 在 AI 不确定或需要人工处理时转人工；
- 对回答进行反馈。

运营人员可以：

- 管理知识库；
- 查看会话、引用和工具调用记录；
- 处理人工工单；
- 查看低分回答、未解决问题、Token 成本和延迟。

### 明确不做

- 不接真实淘宝、京东或支付系统；
- 不执行真实退款、赔付、改地址；
- 不做多租户 SaaS；
- 不做 OCR、图片售后、语音和外部客服渠道；
- 不做多 Agent 自主协作；
- 不做模型微调；
- 不安装 Docker，不做公网部署。

## 3. 约束与选型

| 约束 | 决策 |
|---|---|
| 电脑配置有限 | 不运行本地模型；Embedding、对话和重排全部走 API |
| RAG Embedding | 硅基流动免费 `BAAI/bge-m3` |
| 对话与工具调用 | DeepSeek `deepseek-flash` |
| 向量存储 | 本地 Chroma，`PersistentClient`，不启动独立服务 |
| 业务数据库 | 本地 MySQL 5.7 |
| 安装位置 | 新增 Python、依赖和缓存放 D 盘 |
| 不必要升级 | Node 22.20.0 已满足 Vite 要求，不升级、不重装 |
| 部署 | 先本地完整运行，不上公网、不装 Docker |
| 数据 | 全部使用虚构商品、订单、客户和售后文档 |

### 技术栈

```text
浏览器
  └─ Vite + React + TypeScript
       └─ FastAPI + Python 3.12
            ├─ LangGraph Agent（已接入）
            ├─ DeepSeek API：SSE 流式回复（已接入）
            ├─ SiliconFlow API：BGE-M3 Embedding（已接入）/ Reranker（M6）
            ├─ Chroma：本地向量索引（已接入）
            ├─ 业务工具：订单 / 物流 / 售后判断 / 人工工单（已接入）
            └─ MySQL 5.7：业务事实源
```

MySQL 保存订单、知识文档、切片正文、会话和工单；Chroma 只保存向量和 chunk ID。  
即使 Chroma 索引被删除，也可以从 MySQL 重新生成。

## 4. 核心链路

### 知识入库

上传文档 → 解析 Markdown / TXT / PDF / DOCX → 按标题与段落切片（约 600 字符、80 字符重叠）→ 批量调用硅基流动 BGE-M3 生成 1024 维向量 → 正文写入 MySQL → 向量写入 Chroma（cosine）→ 记录 `pending / indexed / failed` 状态。

### 问答

用户提问 → 保存匿名会话 → LangGraph 意图路由 → 知识检索 / 订单物流工具 / 售后判断 / 人工工单 → 组装历史、参考资料和工具结果 → DeepSeek 流式生成 → 引用与安全检查 → 答不了则拒答/建议转人工。

当前可查询演示订单、物流，能判断售后条件并创建人工工单；真实退款、改地址和赔付仍不执行。

运营侧在 M5 增加会话中心、工单处理、用户反馈、知识缺口和 token/延迟/成本洞察，形成从顾客提问到人工闭环的完整工作台。

### 工具边界

订单、物流、售后条件都是只读工具或低风险工具。任何涉及资金与真实履约的动作不在本项目范围内。

## 6. 数据与安全

- 所有客户与订单数据为合成数据；
- API Key 仅保存在本地 `.env`；
- 后台密码使用 scrypt + 随机盐；
- 登录使用服务端会话令牌，浏览器只保存 HttpOnly Cookie；
- 业务工具采用白名单、参数校验、MySQL 查询超时、单轮调用上限与审计日志；
- 订单、物流只读；转人工只创建工单；真实退款、改地址与赔付不执行；
- RAG 引用必须保留来源，低置信度时优先拒答或转人工；
- 消费者会话使用随机 public ID；当前还不具备登录鉴权和限流，正式上线前必须补齐。
